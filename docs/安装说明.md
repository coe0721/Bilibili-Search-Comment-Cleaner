# B站搜索与评论净化 v0.18（淡化程度自定义版）

## 功能

- 默认开启“低赞直接过滤”：点赞数小于等于阈值时独立生效，不受用户等级影响。
- 明确广告和自定义屏蔽词属于强规则；高赞只保护普通的短句、表情、重复句式等通用低信息信号，不保护广告和自定义屏蔽词。
- 关闭“低赞直接过滤”后，低赞才改为与零回复、短内容、低等级、低信息套话叠加计数。
- 置顶和 UP 主互动保留；高等级不会保护普通的零赞评论，也没有单独的“图片评论识别”功能。
- 可以设置自定义屏蔽词和最低用户等级；等级过滤默认关闭。
- 脚本会自动开启一次“按点赞重排”。默认使用“分批排序”：首批评论按赞排序；后来加载的评论只在同一新批次里按赞排序，并接在已读批次之后，所以新出现的高赞评论不会自己跳到页面前面。
- 排序页还可选择“保持B站加载顺序”（只排序首批，后来的不排序）或“加入全部评论重新排序”（传统全局排序，新高赞可能跳到前面）。
- 排序只使用 CSS `order` 改变显示顺序，不移动或重建 B 站评论节点；关闭后恢复 B 站顺序。
- 视频页和动态详情页会处理当前网页已加载的全部新版评论区，不主动批量请求评论接口。v0.15.1 同时匹配 `space.bilibili.com` 和 `t.bilibili.com`：个人空间动态列表外层不主动处理，展开评论区或进入 `t.bilibili.com/动态ID` 详情页后才处理。
- 可以显示被过滤的评论、关闭并恢复评论，或恢复默认设置。
- 搜索页同时处理明确广告/付费课程、最低播放量、最低点赞播放比和“明显无关标题”。
- 点赞播放比默认关闭；开启后只查询即将进入屏幕的普通视频，最多2个并发、每次启动间隔900毫秒，成功数据缓存10分钟；连续失败3次会暂停3分钟。
- 点赞播放比的最低样本播放量默认1000。播放不足、接口失败或无法取得BV号时保守放行，不会把“未知”当作低质量。
- 相关度在本地综合完整搜索词、核心词、近似词、中文文字覆盖、UP主名称、二创特征和结果位置；分为“相关、不确定、明确无关”三态，不确定结果默认保留。
- 智能判断可选“保守、均衡、严格”三档，默认均衡；不使用AI、不上传搜索内容，通常在毫秒级完成。
- 可选“用 B站视频标签复核无关结果”：只对本地准备判无关、且即将进入屏幕的视频读取公开标签；标签只允许救回，不会把原本保留的视频改判为无关。
- 本地判断明确无关时会立即淡化，不再等标签接口；标签在后台只负责“救回”。即使最终设置为隐藏，复核中也先淡化，避免结果先消失后回来导致页面跳动。
- 标签为空、没有BV号、超时或连续失败时仍保守放行；成功缓存30分钟，最多4个并发、每次启动间隔200毫秒，连续失败3次暂停3分钟。标签与赞播比预取范围扩大到屏幕前后约1600像素，减少滚动后才开始处理的迟滞。
- 标签请求使用匿名模式，只把公开BV号发给 `api.bilibili.com`，不发送搜索词、标题、评论、登录 Cookie 或 DeepSeek API；v0.11 按用户要求自动开启，仍可随时关闭。
- “明显无关标题”默认只淡化；角色昵称、CP名、作品简称可写入“搜索白名单/别名”。白名单只保护相关性，低播放和低赞播比仍独立生效；明确广告仍会拦截。
- 由每 1.8 秒扫描整页改为 MutationObserver 事件驱动；只有评论或搜索结果发生变化时才重新检测。
- 隐藏/淡化改为稳定属性和一次性样式，不再反复删除、恢复、重写内联样式。
- 淡化透明度降至 7%，取消边框和渐变动画；鼠标移到淡化内容上会显示具体原因。
- 评论隐藏不再使用 `display:none`，而是保留 12 像素不可见加载锚点，避免滚动加载被卡住。
- 提供“用 Bing 精确搜索 B站视频”，只有手动点击后才会打开站外搜索。
- 面板按“评论 / 搜索 / 排序”分为三页，页内设置默认全部展开；标题栏和内容滚动区完全分离，顶部 `×` 始终可见但不会遮挡表单。也可按 `Esc` 或点击面板外收起。圆形“评”按钮可以拖动，位置和所有开关均由油猴专用存储持久保存。

## 安装

1. 在 Edge 安装正式版 Tampermonkey。
2. 地址栏打开 `edge://extensions/`，开启“开发人员模式”；如果 Tampermonkey 的扩展详情中出现“允许运行用户脚本”，也将其开启。
3. 点击 Tampermonkey 图标，选择“添加新脚本”。
4. 删除编辑器中原有的示例代码。
5. 用记事本打开 `bilibili-comment-cleaner-v0.1.user.js`，全选、复制并粘贴到 Tampermonkey 编辑器。
6. 按 `Ctrl+S` 保存。
7. 打开或刷新任意 B 站视频，向下滚动到评论区。
8. 点击右下角粉色“评”按钮打开设置。

文件名继续沿用 `v0.1` 是为了方便覆盖之前的同一份脚本；实际版本请看代码顶部的 `@version 0.18.0`。

保存脚本时，Tampermonkey 可能提示访问 `api.bilibili.com` 的权限。这仅用于用户主动开启的点赞播放比或视频标签复核；两个功能都关闭时不会发起视频信息接口请求。

保存成功后，在 B 站首页、搜索页、视频页、个人空间动态页或 `t.bilibili.com` 动态详情页刷新一次，页面上方会短暂显示“B站净化 v0.18 已启动：评论与搜索淡化程度可分别设置”。首次增加空间页或动态详情页权限时，Tampermonkey/Edge 可能要求你重新确认脚本权限。

## 保存后完全没反应

1. 地址栏输入 `edge://extensions/` 并回车。
2. 确认 Tampermonkey 卡片的开关为开启状态。
3. 打开 Tampermonkey 的“详细信息”，如果能看到“允许用户脚本”，将它开启。
4. 回到扩展管理页，开启“开发人员模式”。
5. 点击浏览器工具栏的 Tampermonkey 图标，确认顶部总开关和“B站评论净化与手动排序（Codex 初版）”右侧开关都为开启。脚本名称保留不变，是为了覆盖旧版本而不是额外安装一份。
6. 完全关闭并重新打开 Edge，然后进入 `https://www.bilibili.com/`，按 `Ctrl+R`。
7. 若仍没有绿色提示和粉色“评”按钮，说明脚本没有被 Edge 执行，并非评论规则失效。

## 建议第一次测试

1. 先打开“显示被过滤评论（变淡）”，观察过滤是否符合预期。
2. “最低用户等级”保持关闭。
3. “低赞阈值”先保持 1，并开启“低赞直接过滤”；0赞或1赞会独立过滤，高等级不会抵消。
4. 如果不想过滤刚发布的长评论，可关闭“低赞直接过滤”，再用“普通规则命中数”控制叠加判断。
5. 确认过滤结果后，再关闭“显示被过滤评论”。
6. “自动按点赞重排评论”在本次升级会开启一次，并把“后来加载的评论”设为“分批排序，不跳回前面”；无需再点“立即检测/重排”。如果关闭，脚本会记住你的选择并恢复 B 站顺序。
7. 搜索页建议：广告过滤开启、最低播放量 1000，“明显无关结果”保持“淡化”，“智能判断强度”先用“均衡”；误杀明显时改“保守”，不建议一开始使用“严格”。
8. “用 B站视频标签复核无关结果（匿名）”会自动运行，不需要每次手动点击。待复核结果先淡化，标签确认相关后自动恢复；观察面板里的“标签救回”数量即可。
9. 如果角色昵称或 CP 名仍被淡化，把代表该内容的词加入“搜索白名单/别名”，每行一个。例如填写 `芙宁娜=芙芙`。没有等号的词会对所有搜索生效；低播放量和低赞播比仍按各自规则处理。
10. “低点赞播放比”默认关闭。建议第一次设为“淡化”，最低赞播比先用 `1%`，最低样本播放量保持 `1000`；悬停检查原因后再决定是否隐藏。
11. v0.11 升级时会自动开启标签复核一次；如果你不想使用，关闭开关后该选择会永久保存，不会在下次刷新时重新开启。

## v0.18 淡化程度自定义

- 评论页和搜索页分别提供“淡化后可见度（%）”，可直接输入 `1–100` 的任意整数。
- 数值越小内容越淡；默认仍为 `7%`，两种内容互不影响。
- 修改后立即生效并保存，刷新页面不会恢复默认值。
- 鼠标移到淡化内容上时会临时提高可见度并继续显示淡化原因。

## v0.17.3 拖动定位修复

- 拖动时记录指针在圆形按钮内的实际按下位置，按钮不会突然跳到鼠标中心。
- 统一使用当前可视窗口坐标，在窗口缩放、尺寸变化或浏览器可视区域变化后自动校正。
- 设置面板会跟随圆形按钮；靠近屏幕底部时显示在按钮上方，靠近顶部时自动显示在下方。
- 面板和按钮都限制在屏幕安全边距内，拖到左右边缘后不会错位或跑出视野。

## v0.17.2 面板交互优化

- 标题栏与内容区改成独立布局，不再使用压在内容上方的悬浮标题；滚动设置时不会发生遮挡。
- 顶部 `×` 只收起设置面板，不会改变任何过滤或排序开关。
- 按 `Esc` 或点击面板外也可以收起面板；底部原有按钮继续保留。
- “停用全部并恢复”留在底部，并使用不同颜色提示它会关闭全部净化功能，减少误触。
- 评论规则、播放量与赞播比、相关度设置均默认展开，打开面板即可看到，不需要逐项点开。
- 切换“评论 / 搜索 / 排序”时自动回到内容顶部；增加键盘焦点样式和窄屏单列布局。

## v0.16 稳定性自审优化

- 分批排序改成确定性状态：首批一旦建立，后来评论即使在100毫秒后出现也不会并回首批，更不会因“仍在2.2秒加载期”而跳到已读区域。
- 如果B站切换评论视图或整批重建自定义元素，脚本通过“新旧节点完全无重叠”识别为一份新列表；“仅首批排序”不会因此永久失效。
- 动态页新插入 `bili-comments` 组件时由轻量节点观察器即时接管，并补一次260毫秒复核；不再主要依赖最长1.2秒的兜底轮询。
- 全页评论宿主观察器只在视频、动态、番剧、专栏等可能出现评论的页面启用，首页等无评论页面不承担这部分监听开销。
- 搜索页标签和赞播比的待观察卡片改为可清理集合；无限滚动移除旧卡片后会主动 `unobserve`，避免观察器长期持有已离页节点。
- 搜索处理也会清理已断开的评论、卡片和内部 Shadow DOM 观察器，长时间翻页占用更稳定。
- 关闭、切页或重开标签/赞播比功能时立即隔离旧代请求，并重置当前代并发计数和启动节流；旧请求结束不会扣减新一代计数。
- 连续失败触发3分钟熔断后，已经在途的偶然成功响应不能提前解除保护；到期或用户主动重启功能后才恢复。
- 没有新增网络权限、第三方AI或评论接口；设置和 v0.15 保持兼容，不会重置你的阈值与开关。

## v0.15 分批排序、动态页与搜索速度修复

- v0.15.1 补充 `t.bilibili.com/*` 匹配。实页确认该域名不会自动跳转，评论区使用脚本已经支持的 `bili-comments` 开放 Shadow DOM，因此无需另一套排序逻辑。
- 默认“分批排序，不跳回前面”：首批全量按赞排；每次滚动新加载的一批评论只在本批内部按赞排，并追加在先前批次之后。
- 新增“保持B站加载顺序”：只排序首批，后来评论完全按B站加载顺序显示；适合最讨厌页面变化的情况。
- 保留“加入全部评论重新排序”：每次加载后都对当前全部评论重排；最接近全局高赞榜，但新高赞可能跑到已经看过的上方。
- 不自动滚动或批量请求全部评论。B站评论是分页加载的，前端脚本只能排序当前已经加载的数据；强行自动加载会产生大量请求、卡顿，并破坏阅读位置。
- 新增 `space.bilibili.com` 匹配，修复原神等账号个人空间动态页上脚本根本没有启动的问题。外层动态列表保持原样，展开的新版评论区会被独立观察和排序。
- 搜索本地判无关后立即淡化，标签复核异步救回；不再因为等待标签而下滑很久后才变化。
- 标签和可选赞播比的屏幕预取范围从650像素提高到1600像素；仍有限并发、缓存、匿名请求和失败熔断。

## v0.14 按需读写优化

- 评论质量判断按“正文、点赞、回复、等级、置顶状态和当前规则”缓存；输入完全相同时不再重复运行正则和有效字符统计。
- 搜索相关性按“搜索词、标题、UP主、位置、标签/简介和强度”缓存；其它视频的标签返回时，不再重新判断已经稳定的卡片。
- 正常评论和正常搜索结果不再反复执行无效的属性删除。
- 评论重排时先比较现有 `order`；位置没有变化的评论不再重写样式，只有新增评论影响到的名次才改变。
- 面板的复选框、输入值、禁用状态和统计文字都改为值变化时才写，降低连续检测造成的UI开销。
- 没有扩大网络范围或新增功能；仍然只服务于搜索过滤和评论点赞排序。

## v0.13 增量高速优化

- 稳定评论的数据保存在内存弱缓存中；任意评论发生变化时，只重新穿透读取这一条评论的 Shadow DOM，不再重读整页正文和点赞节点。
- 搜索标题、UP主、BV号、广告标记和播放量按卡片缓存；标签或赞播比接口返回时，稳定卡片不再重复执行整套 DOM 查询。
- 搜索结果监听会精确标记发生文字、链接或标题变化的卡片；B站复用卡片时仍会正确失效，不以缓存换取错误结果。
- 搜索卡片去重从逐卡两两比较改为向上查找匹配祖先，避免结果较多时出现平方级扫描。
- 标签复核调整为最多4个并发、启动间隔200毫秒；继续保留屏幕附近优先、同BV去重、30分钟缓存、失败放行和连续失败熔断。
- 评论与搜索缓存仅存在当前网页内存，切页时清空，不写入磁盘，也不增加任何第三方请求。

## v0.12 搜索与排序重点修复

- 搜索“相关性”和“质量”拆开判断：标题/标签命中白名单只解决误杀，不再放过低播放或低赞播比。
- 本地明确无关的视频由公开标签和已有简介单向复核；元数据只能救回，接口失败时放行，不会扩大屏蔽范围。
- 标签队列优先处理屏幕附近结果，并调整到最多3个并发、启动间隔300毫秒；同一BV号去重和缓存策略不变。
- 评论默认按点赞数降序显示，置顶优先；首次加载、新增评论、点赞数据刚就绪时才重新计算，稳定后停止反复排序。
- 排序通过 CSS 显示顺序完成，不搬动评论 DOM，避免头像、回复区、加载按钮和组件内部状态丢失。
- 同时监听动态页中的多个新版评论区，新增评论区也能独立触发检测与排序。
- 没有图片专用判断。高赞统一保护普通低信息信号；明确广告和自定义关键词仍然优先。
- 面板拆分为“评论 / 搜索 / 排序”三页，次要参数放入折叠区。

## v0.11 自动触发修复

- 修复搜索结果在脚本首次扫描之后才加载时，标签复核必须点击“立即检测/重排”才生效的问题。
- 扩充B站搜索结果容器识别；找不到精确结果区时，自动监听页面主区域或 `#i_cecream`。
- 最后才使用 `document.body` 兜底，而且只监听节点新增/删除，不监听全页文字变化，避免高频重复计算。
- 进入搜索页、站内翻页、异步加载新卡片以及滚动到新候选时都会自动启动标签复核。
- v0.11 会自动开启标签复核一次；之后手动关闭会正确持久保存。

## v0.10 新增和优化

- 增加B站公开视频标签二级复核，解决标题使用梗、台词、简称或画面内容、没有直写角色名时的误杀。
- 固定采用单向安全规则：本地已判断相关或不确定的不查询；只有准备判“明确无关”的结果才复核，元数据只能救回，不能扩大过滤范围。
- 请求前先检查是否已有点赞播放比返回的视频分区、简介、动态文案和分P标题；已有信息会与标签一起判断，不重复调用体积很大的详情接口。
- 只观察距离屏幕约650像素内的候选卡片，不预取整页；标签接口最多2个并发、每次启动至少间隔1秒。
- 同一BV号会话内去重，成功缓存30分钟、失败缓存3分钟，缓存最多约300项。
- 查询期间不先淡化或隐藏，避免“先消失再回来”；接口异常、无标签、无BV号都保守放行。
- 连续3次失败自动清空等待队列并暂停3分钟；SPA切页和关闭开关时隔离旧请求，旧页面响应不会写回新页面。
- 没有引入 DeepSeek 或其他第三方AI，不需要API Key。标签接口是B站网页公开接口，若以后变化，熔断和失败放行会避免把异常当作无关。

## v0.9 新增和优化

- 将旧版“核心词没有出现就判无关”改成三态本地智能判断：相关、不确定、明确无关。
- 不确定结果直接放行，尤其保护角色昵称、CP名、二创标题、中文同义表达和排名靠前的灰区结果。
- 除标题外增加UP主名称信号；例如标题只写“零基础教程”，UP主名称明确包含搜索主题时仍可识别为相关。
- 增加小范围近似词匹配和中文主题文字覆盖，处理部分拼写差异，同时避免重量级分词库或远程模型。
- 扩充“基础、零基础、新手、课程、全套、实战、讲解”等泛词，防止因为大家都写“入门教程”就被误认为同一主题。
- 专门保留 `C++`、`C#` 的区分度，不让它们在规范化后退化为单字母 `c`。
- 提供保守、均衡、严格三档：保守档给更多灰区结果机会，均衡档更积极清理，严格档接近旧版行为。
- 性能回归中，模拟42个搜索结果重复100遍共4200次判断约84毫秒；折算一页本地判断约0.84毫秒，不产生网络等待。

### 为什么本版暂时不用 DeepSeek

- 若每条视频单独调用AI，网络往返和模型生成会明显慢于本地判断，而且页面会不断改变。
- 更合适的架构是：本地立即完成大多数判断，只把少量“不确定”结果合并成一次请求，AI异步复核；设置短超时、失败放行并按“搜索词+BV号”缓存。
- DeepSeek接口支持关闭思考模式和结构化JSON，技术上可以实现；但官方说明请求有时可能等待较久，因此AI不能成为页面显示的前置条件。
- 接入AI还意味着把搜索词、视频标题和UP主名称发送给第三方，并需要保存API Key，必须由用户明确开启。v0.9不会连接DeepSeek，也不需要API Key。

## v0.8 新增和优化

## 安全说明

- `GM_getValue` 和 `GM_setValue` 只用于保存设置；`GM_xmlhttpRequest` 只用于已开启的点赞播放比。
- `@connect` 仅允许 `api.bilibili.com`；没有通配域名、`@require`、第三方接口、外部脚本或统计代码。
- 查询使用匿名模式，只发送当前公开搜索结果中的BV号，不发送 Cookie、搜索历史、账号资料或评论内容。
- 点赞播放比关闭时不请求接口；评论过滤、标题相关度、广告和页面播放量过滤仍完全本地运行。
- 不读取、导出或上传 Cookie、账号凭证和评论内容。
- 设置写入 Tampermonkey 为本脚本隔离的专用存储，不写入账号资料。
- 过滤通过隐藏/淡化网页节点实现，不会删除或举报 B 站上的真实评论。

## 当前限制

- 只适配新版 B 站视频、播放列表及番剧播放页的开放 Shadow DOM 评论区。
- 只重排已加载的一级评论，不抓取整个评论区；需要查看更多评论时先继续下滑。
- B 站更新页面结构后可能需要更新脚本。
- 评论重排只改变 CSS 视觉顺序，不改变 DOM 顺序；不会自动跟随点赞数持续重排。
- 用户等级、回复数等字段若当前页面没有提供，脚本会保守地不据此过滤。
- 搜索卡片标题或播放量无法从当前页面识别时不会猜测；面板会显示“播放量未识别”的数量。
- 点赞播放比依赖B站未承诺长期稳定的公开接口，遇到限流、风控、超时或接口变化时会放行；连续失败时面板显示“接口保护暂停”，3分钟后才恢复尝试。
- 本地智能相关度仍不是大语言模型，不能真正理解所有隐喻、别名和语境。默认保守并将灰区放行；搜索白名单仍是修正已知别名最可靠、最快的方式。
- 搜索净化只能过滤 B 站已经返回的结果，不能让 B 站服务端吐出它原本没有返回的视频；需要补充结果时可手动点击站外精确搜索。
